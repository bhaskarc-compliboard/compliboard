## The planted gaps — what this suite was built to measure

Six gaps were deliberately written into two fixtures. **Found** means a gap in the reading carries
at least two of the spec's keywords for it — the citation is judged separately, in the column beside
it, because a gap found and miscited is a different result from a gap missed. `n/3` is how many of
the three runs found it.

> ### THE LAST COLUMN IS NOT A VERDICT ON THE MODEL.
>
> It says only whether the citation string **contains the rule number the spec names**. It reads
> **NO** for a citation that is arguably better than the answer key's: Oregon is a state-plan state,
> and `OAR 437-002-0042(2)(c)` is the rule that actually governs a Portland employer, where
> `29 CFR 1910.38(c)(1)` is the federal standard Oregon adopted. A model that cites the OAR alone
> is cited correctly and marked NO here. See "Where the spec looks wrong".

Each was decided by the owner from the first report's "Where the spec looks wrong" section. The
original report and the original per-run verdicts are both still on disk: **no answer changed, only
the questions did.**

| | Correction | Where | What it moved |
|---|---|---|---|
| 1 | A record's status accepts `recorded` **or** `gaps_found` | `06a`, `06b` cases + spec 06 | Six configurations had failed both record cases on a line only the weakest model passed. A record with findings is now expected to read `gaps_found` until the contract carries a separate findings flag |
| 2 | A planted gap accepts the **governing state rule or the federal one** | `01` gaps (`citation_any`) + spec 01 | Opus 5.5 had failed three gaps it found correctly in every run, for citing `OAR 437-002-0042` instead of `1910.38(c)(N)`. Case 04's 117 sections are unchanged |
| 3 | The photograph's last-entry date and two footer deadlines are **reported-only** | `06b` case + spec 06 | The spec had paid full marks for declining to read the photo and failed every model that read it 90% right. `06a` still carries all three as musts |
| 4 | The supplier moves to **Tacoma, Washington**; fixture re-rendered | spec 05 + fixture | `site-not-invented` can finally distinguish "read the company's only site" from "lifted the supplier's city". **N/A for these stored runs** — they read the old fixture |
| 5 | A proposal that **names itself as not about the company is still a proposal** | spec 05 | Nothing moved, deliberately. Opus 5's `emergency_shower_eyewash_location` stays a failure: a person confirms the row, not the parenthesis inside it |
| 6 | Labels compared as **sets**; "order is not compared" | `README.md` + runner | The largest single source of failures in the first report, and none of them a model error |

### ⚠ And one correction that is deliberately NOT a correction

**Correction 2 requires the rule number `437-002-0042` and NOT a paragraph letter.** The models
asserted a mapping — reporting `(2)(c)`, critical operations `(2)(d)`, contact `(2)(f)` — consistently,
across models and runs. **Nobody has read the OAR to check it.** Writing a paragraph into an answer key
on the strength of model output would put an unverified regulatory claim in the one place this suite
can never question again — `CLAUDE.md` §1's *"AI generates, human verifies"* inverted. The paragraphs
should be pinned once a person has read the rule, and spec 01 carries that note so the gap is a
recorded decision rather than an omission.

### What is still wrong after all six

**`06a status` is fixed as a line and remains a product defect.** `ScanStatus` still makes one field
answer two unrelated questions, and the correction only stops the suite punishing models for it.
Splitting it is a column, a migration and a display decision — not a bake-off change.

**`06b` still has no model taking the honest-refusal exit.** Correction 3 stopped the perverse scoring;
it did not make any model say "this is a photograph and I am not sure". That every configuration reads
a photographed page confidently, and gets the last entry one day wrong, is a finding the suite now
reports rather than fails — and it is the one most worth a person's eyes.

**Case 04's `fact-address` and `deadline-*` lines still fail widely** and were not reviewed for this
round. They are the next candidates, on the same logic: a line every model fails is measuring the line.

### What this bake-off does NOT say

**It does not say which model is best.** `Cases passed` is dominated by items 1, 2, 4 and 6 above —
three answer-key problems and a matcher bug — so the column that looks like a score is mostly
measuring the suite. The honest readings are the narrower ones: **who found the planted gaps** (every
Opus configuration, all three, all runs), **who invented facts** (Opus 5 and Haiku), **who parsed**
(everything, always), and **what it cost** (13× between the ends of the range).

**And it cannot say whether an answer is good.** `TESTING.md` is explicit that the golden set can only
tell you the output moved. Case 01's readings are a worked example: every configuration raised gaps the
spec never mentions — a missing chemical-spill response procedure, no OERS notification step, the
appendices referenced but absent, no revision history. Those are plausibly the most useful findings in
the whole run and **this suite scores them zero either way.**
